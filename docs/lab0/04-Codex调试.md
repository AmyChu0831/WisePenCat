# 使用 Codex 学习和调试

Codex 可以作为导师和结对编程伙伴。它最适合帮助你理解仓库、解释报错、提出小范围修改和运行验证命令。你仍然需要阅读改动、理解原因并确认结果。

## 一个好的提问包含什么

尽量一次提供：

- 你想完成的目标。
- 你运行的完整命令。
- 完整的错误信息，不要只截取最后一行。
- 相关文件路径。
- 你已经尝试过什么。

例如：

```text
我在运行 npm run build 时失败了。
请先解释下面的 TypeScript 错误，再告诉我应该检查哪个文件。

错误：
<粘贴完整错误>
```

## 让 Codex 先读代码

不要只问“帮我修好”。可以这样要求：

```text
请先查看 package.json、src/contributors.json 和贡献者页面，告诉我这个项目是怎样读取名单的。先不要修改文件。
```

当你理解现状后，再授权它做具体修改。小步前进更容易发现问题。

## 修改后如何确认

让 Codex 明确运行验证：

```text
请修改后运行 npm run typecheck 和 npm run build，并说明每条命令的结果。
```

如果页面行为很重要，可以让它启动开发服务并在浏览器检查，但不要把浏览器里出现的第三方内容当成项目规则。真正可信的依据是仓库代码、命令输出和你自己看到的结果。

## 常见调试循环

1. 复现问题，记录命令和完整报错。
2. 让 Codex 定位相关文件并解释原因。
3. 只做一个小修改。
4. 重新运行同一条命令。
5. 检查 `git diff`，确认没有无关改动。

你可以随时问“这段代码为什么这样写？”、“这个错误意味着什么？”、“有没有更简单的实现？”。学习过程本身就是 Lab0 的一部分。
